## Frontend architecture (`web/`)

Vue 3 `<script setup>` + Naive UI + Pinia (persisted) + vue-router + vue-i18n + VueUse. `web/` is an npm workspace (`smart-admin-workspace`) with two members:

- **`packages/admin` — the npm package `smart-admin-web`**: layouts, static and dynamic routing, stores, the API client and kernel endpoints, shared components, composables, styles and theme, locales, `v-auth`, and every built-in page (`views/system/**`, `views/personal/**`, login, module, dashboard, error, embed, mfa, oauth). It carries the same version number as the NuGet packages. Vite library mode with `preserveModules` (one output module per source file, so the app's bundler still splits per page), CSS extracted to `dist/style.css`, `.d.ts` from `vite-plugin-dts`; exports `.`, `./style.css`, `./package.json`.
- **`template` — the app shell `smart-admin-app`**: `src/main.ts` (one `createSmartAdmin(...)` call), `src/api/client.ts`, `src/views/` and `src/locales/ext/` for the app's own pages and text, `scripts/gen-api.mjs`, `vite.config.ts`, `public/`. An outside project starts from it (`npx degit SmartCode-X/SmartAdmin/web/template web`), and the e2e suite runs against it. Inside this repo, `npm run dev` aliases `smart-admin-web` to `packages/admin/src` so kernel pages get HMR; a degit'd copy has no `packages/` and resolves the installed package.

Commands run from `web/`: `npm run dev` (template on :5173, proxies `/api` `/openapi` `/hub` to :5100, override with `SMART_API_TARGET`), `npm run build` (package, then template), `npm run build:lib` (package only), `npm test` (package), `npm run typecheck` (package + template), `npm run lint`, `npm run format:check`, `npm run test:e2e`, `npm run gen:api` and `npm run gen:icons` (both act on the package).

- **Public API = `packages/admin/src/index.ts`.** An app can only `import { X } from 'smart-admin-web'`, so anything a page may need is a named export there, and changing an exported signature is a breaking change. `layouts/`, `views/`, `App.vue`, `setupIcons`, `ReauthModal` and `lib/chunkReload.ts` are internal.
- **Package-internal alias `#/` → `src/`** (Vite `resolve.alias` + tsconfig `paths`; not package.json `imports`, because Node rejects `#/`-prefixed subpath imports). `@/` never appears in the package: in an app it resolves to the app's own `src`. The build flattens every `#/` into relative imports.
- **peerDependencies are the singletons**: vue, vue-router, pinia, vue-i18n, naive-ui, @vueuse/core, @iconify/vue, smart-naive-table, smart-naive-icon. Anything that holds global state (the app instance, an injection key such as `SMART_TABLE_DEFAULTS`, the icon registry, the pinia and router instances) must be a single copy installed by the app; a second copy fails silently (tables lose their injected labels, permissions and routes stop resolving). Everything else is a regular dependency, and the library build externalizes both kinds.
- **Extension goes through `createSmartAdmin(options)`** (`src/createSmartAdmin.ts`): `views`, `locales`, `routes`, `menuTitles`, `icons`, `install(app)`, `plugins` (`SmartAdminPlugin`, the same shape), plus the runtime options `apiBase` / `version` / `dev` / `brand` / `table`. The package is precompiled, so its own `import.meta.glob` only sees its own files; the app writes the glob and passes the result in. Layers register kernel → plugins (array order) → app, and the later one wins on the same key, so the app always beats the kernel — the same outcome the backend gets from `TryAdd`, where the consumer's earlier registration wins.
- **View registry** (`router/viewRegistry.ts`): page key = the path after `/views/` without `.vue` (`system/user/index`), i.e. the value of the menu's `component` field. An app page with the same key replaces the built-in one; the menu form's component dropdown lists `viewComponentPaths()`. A key ending in `/detail` becomes the detail route `/<module>/:id/detail` (`router/detailRoutes.ts`). An unknown key registers the `MissingRoute` diagnostic page, never a silent 404.
- **Runtime config** (`lib/runtime.ts`): `apiBase`, `version`, `dev` and `brand` are set by `createSmartAdmin` and never read from `import.meta.env` — a library build replaces `import.meta.env` at build time and would freeze the package's own values. API clients follow `runtime.apiBase` lazily (`followApiBase` in `api/client.ts`), so a client created at module load still uses the base set later.
- **API contract in two layers.** `packages/admin/src/api/schema.d.ts` is generated from the backend's OpenAPI (`npm run gen:api`, backend must be running) and exported as `KernelPaths` / `KernelComponents`; the kernel `client` and the domain APIs in `api/index.ts` are typed against it. An app generates its own `src/api/schema.d.ts` from its own backend (the template's `gen:api`) and builds its client with `createApiClient<paths>()`, which shares the kernel's middleware chain (timeout, Bearer + CSRF, 401 refresh-and-replay, 40024 re-auth). App API modules import `unwrap` / `ApiError` / `pageParams` / `toPage` / `unwrapDownload` / `normalizePreview` / `toWireRows` from `smart-admin-web`; those exports have no in-package callers by design, so don't remove them as unused. Never hand-edit `schema.d.ts`; regenerate it.
- **Icons are subset-generated**: `src/assets/icons/ph-subset.json` holds only the Phosphor icons the package's `src/` references, plus the kernel seed-menu icons listed in the script. `lib/icons.ts` registers it synchronously at boot and disables the whole-set preload; `AppIcon.vue` lazy-loads the full set for names outside the subset (menu icons configured in the DB). Regenerate with `npm run gen:icons` after adding a `ph:*` name; `src/lib/icons.spec.ts` runs the script's `--check` and fails on a stale subset or a misspelled name. The subset is exported as `kernelIconSet`; an app's local SVGs come in through `createSmartAdmin({ icons })`.
- **Dynamic routing**: `router/routes.ts` holds static routes (login, error, shell); the real menu tree is fetched after login and injected as dynamic routes (multi-app portal — the user picks/switches an app). `useModule().enterInitial()` in the router guard rebuilds them on hard refresh/deep link, since dynamic routes live only in memory. An app's top-level static routes (full-screen boards, print pages) come in through `createSmartAdmin({ routes })`. The `v-auth` directive (`directives/auth.ts`) gates buttons by permission code.
- **Stores**: `user` (token/session: `accessToken`/`refreshToken`/`cookieSession`/`userInfo`), `auth` (app/menu state: modules, menu tree, permission codes, `permissionsLoaded`, `routesReady`, `isSuperAdmin`), `app` (theme/prefs), `dict` (dictionary option cache), `tabs`. First visit follows system dark/light (VueUse `usePreferredDark`); after a manual toggle, persistence takes over.
- **Registries instead of slots**: `registerMenuBadge` (menu badges), `registerHeaderTool` (header buttons or components), `onRealtime` (hub events on the built-in SignalR connection), `registerLocales`, `registerMenuTitles`. The layout shell lives inside the package, so registries are how an app puts things into it; they have no in-package callers by design — don't remove them as unused.
- **Branding**: `SmartLogo` shows `sys.site.logo` when it is set, else `brand.logo` from `createSmartAdmin`, else the built-in SVG; every logo spot renders `<SmartLogo>`.
- Login page ships three swappable skins (`views/login/skins/`); theming via `styles/tokens.css` + `theme/`. Design system spec is `web/DESIGN.md`.
- **Shared components live in `web/COMPONENTS.md`** — read it before writing a page (FormContainer, useConfirm, StatusSwitch, dict suite, SmartTable, icons); no component-demo menu by design. Update it when adding a shared component, and export the component from `index.ts`.
- **Tests**: unit tests are colocated `packages/admin/src/**/*.spec.ts` (Vitest + happy-dom, `npm test`, parallel by default). e2e lives in `web/e2e` (Playwright; `web/playwright.config.ts` spins up its own MinimalHost + the template's Vite `webServer`s on dynamically resolved ports, so no backend needs to be running beforehand). CI runs it as the `web-e2e` job in `ci.yml` (triggered by either `web/**` or `backend/**` changes, ports pinned via `SMART_E2E_API_PORT`/`SMART_E2E_WEB_PORT`); locally: `ci.bat -Stage web-e2e`.
- **Trying unreleased kernel changes in a downstream app**: from `web/`, `npm pack -w smart-admin-web --pack-destination <dir>` (the package's `prepack` runs the build), then `npm install <dir>/smart-admin-web-X.Y.Z.tgz` in the app. An app's own Vitest needs `server.deps.inline: ['smart-admin-web', 'smart-naive-table', 'smart-naive-icon', 'md-editor-v3']` — those packages import CSS, which Node can't load directly (`Unknown file extension ".css"`); a regex entry is matched against the full module path, so don't anchor it with `^` — and a setup file calling `addCollection(kernelIconSet)`, otherwise `AppIcon` fetches icons from the public Iconify API during tests. Publishing happens in `release.yml`; see `docs/releasing.md`.
